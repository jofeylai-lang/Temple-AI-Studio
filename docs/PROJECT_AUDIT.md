# 專案分析與結構調整

日期：2026-07-09

## 目前已完成的改善

原本的專案骨架已經具備 AI 專案的基本素材區，例如 `docs/`、`prompts/`、`images/`、`videos/`、`avatar/`、`voice/`、`knowledge/`、`website/`、`telegram/` 與 `archive/`。

這次已補上大型 AI 專案更需要的管理層：

- `strategy/`：專案定位、受眾與長期方向
- `brand/`：品牌識別、品牌語氣與視覺規範
- `research/`：市場、競品、靈感與想法
- `models/`：AI 人設、模型設定與實驗紀錄
- `workflows/`：內容生產、審核與自動化流程
- `evaluations/`：提示詞測試、品質評估與基準檢查
- `datasets/`：原始資料、整理資料與授權資料
- `outputs/`：草稿、正式發布成品與報告
- `channels/`：跨平台發布渠道規劃
- `operations/`：日常營運、SOP 與檢查清單
- `legal/`：授權、隱私、合約與使用權紀錄
- `finance/`：預算、定價、支出與商業資料

## 原本缺少的東西

- 品牌規範區：缺少品牌語氣、視覺一致性與識別管理。
- 策略區：缺少定位、受眾、商業方向與長期路線。
- 評估區：缺少提示詞品質、回答品質與內容品質的檢查區。
- 資料治理區：缺少資料來源、授權狀態與整理後資料的分層。
- 輸出區：缺少已發布成品、草稿與報告的集中管理。
- 營運區：缺少 SOP、檢查清單、排程與日常工作流。
- 法務與授權區：缺少圖片、聲音、影片、資料來源的使用權管理。
- 財務區：缺少預算、定價與支出紀錄。

## 命名調整建議

已保留原本指定的資料夾名稱，避免破壞你的初始規劃，同時加入更專業的補充資料夾。

需要特別注意的命名：

- `scripts/` 容易被誤解成程式碼，所以已在說明中明確定義為「內容腳本」。
- `knowledge/` 已拆出 `sources/`、`faq/`、`policies/`、`references/`，讓知識庫更適合長期維護。
- `website/` 與 `telegram/` 保留為專門渠道，同時新增 `channels/` 管理跨平台策略。
- `images/`、`videos/`、`avatar/`、`voice/` 保留為素材區，並加入更清楚的子分類。

## 未來使用原則

- 根目錄只放總覽與全域設定，不放散亂素材。
- 每個資料夾都應該有明確用途，避免同一份資料被複製到多處。
- 重要內容應該有版本號，例如 `v01`、`v02`。
- 對外發布內容放入 `outputs/published/`。
- 暫時不用但可能有價值的內容放入 `archive/`。
- 有授權風險的素材必須同步記錄到 `legal/usage-rights/`。
