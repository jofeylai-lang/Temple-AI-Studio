# Temple Product Video Generator - Video Quality Corrective Rebuild

Date: 2026-07-25

## Acceptance Result

The rejected production path was reproduced from the real project
`project-20260725-09a499d0`. The replacement path was exercised with the same
Traditional Chinese request and a 30-second vertical output, matching the
duration stored by the rejected project.

Result: **PASS after manual contact-sheet review and automated editorial QA.**

## Proven Root Cause

1. **One image dominated the video.** Text-only generation created
   `text-only-source.png` as the only general visual source. Five of six scenes
   reused it; only one scene used an Emma reference.
2. **Storyboard scenes did not create distinct assets.** Scene prompts existed,
   but the old local image path repeatedly composited the same source instead of
   selecting a scene-specific source.
3. **The renderer substituted a slideshow.** Every scene entered the FFmpeg
   still-frame renderer because no generated video artifact was attached to the
   scene.
4. **The camera shook.** The old zoom path combined frame-stepped `zoompan` with
   `sin(on/30)*10`, producing visible horizontal oscillation.
5. **The old score was not an editorial score.** The reported score of `0.9265`
   was the mean of still-image checks. It did not measure unique scenes,
   repeated assets, frame repetition, camera jitter, motion development, or
   commercial watchability.
6. **Configured providers were bypassed.** The rejected report identifies
   `local_ffmpeg_motion`; it contains no Wan artifact or ComfyUI prompt ID.
   MuseTalk was also not executed: lip sync was waiting for audio. The final MP4
   was primarily FFmpeg animation of still images.

## Corrective Implementation

- Text-only Emma projects now draw from multiple approved identity anchors and
  approved Emma source videos.
- Every rendered scene records its root source, rendered source, render mode,
  source hash, and motion signature.
- A real ComfyUI Wan 2.2 TI2V scene is mandatory for the selected generated
  scene. Failure is visible; it does not silently fall back to a still.
- Product detail uses a dedicated product crop with subtle deterministic motion.
- Approved Emma B-roll supplies genuine motion for appropriate scenes.
- Camera movement uses fixed linear paths. Random and sinusoidal frame offsets
  are prohibited.
- A 20-second-or-longer video requires at least five meaningful scenes, five
  unique root assets, at least two motion-video scenes, no dominant asset, and
  non-repeating camera language.
- Frame QA now measures repetition, visual diversity, freeze ratio, camera
  jitter, motion smoothness, commercial visual quality, and scene-to-script
  alignment.
- Canonical Emma narration is duration-fitted rather than truncated. This test
  used `emma-canonical-video-voice-v1`; the 32-second source narration was
  fitted to 30 seconds at `1.066667x`.
- MuseTalk is not falsely reported as active. This acceptance video uses
  narration over B-roll, so lip sync is explicitly `NOT_REQUIRED`. A future
  direct-to-camera scene must opt in to and complete a real lip-sync stage.

## Remaining Operational Limitation

Wan 2.2 TI2V is genuinely used but is slow on the current local workflow. The
measured first production probe took about 21 minutes, with VAE decode as the
dominant cost. The pipeline therefore uses Wan selectively and combines it with
approved real-motion assets. Product-detail fidelity remains protected by using
the supplied product source rather than accepting a generated scene that loses
the product.
